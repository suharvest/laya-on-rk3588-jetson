# JEV 2026-10-10 Shared Dataset Trial Protocol / 共享数据集试验协议

## Scope / 范围

This trial evaluates forced-choice selection of industrial command candidates for a closed local command set. It measures semantic selection behavior separately from conversion parity and runtime latency. The dataset is frozen before model tuning; prompts, options, and expected labels must not be changed after the checksum is recorded.

本试验评估在封闭本地命令集合中，从工业命令候选项里进行强制选择的行为。语义选择、转换一致性和运行延迟分别测量。数据集在模型调优前冻结，记录校验和后不得修改 prompt、候选项或期望标签。

## Execution matrix / 执行矩阵

Run every row at least once in each language. Preserve row order for the primary pass, then run a second pass with the option order permuted using a fixed seed. Record raw request, returned option id, returned ranking, backend, sequence configuration, and latency. Do not alter prompts or options between passes.

每种语言至少执行每一行一次。首轮保留行顺序，第二轮使用固定随机种子打乱候选顺序。记录原始请求、返回的 option id、完整排序、后端、序列配置和延迟。两轮之间不得修改 prompt 或候选项。

For proportions, report Wilson 95% confidence intervals per language and category. For precision/recall, use `null` when a denominator is zero; do not report zero for an undefined metric.

分别报告：

1. **Semantic accuracy**: top-1 expected-id match, per language, category, scenario, and group. Report full-ranking agreement separately.
2. **Clarification/rejection behavior**: precision and recall for `clarify` and `reject`; do not merge them into ordinary command accuracy.
3. **Order invariance**: top-1 and full-ranking changes after option permutation.
4. **Conversion parity**: compare the same inputs across codec/native/FP32 or other representations. This is a representation comparison, not semantic accuracy.
5. **Latency**: one request, 20 warmups, then 50 measured iterations; report median, nearest-rank p95, min, max, and backend. Do not use the latency sample as a semantic score.

1. **语义准确率**：按语言、分类、场景和语义组统计 top-1 期望标签命中；完整排序一致性另行报告。
2. **澄清/拒绝行为**：分别统计 `clarify` 和 `reject` 的 precision、recall，不并入普通命令准确率。
3. **候选顺序不变性**：比较候选顺序打乱前后的 top-1 和完整排序变化。
4. **转换一致性**：比较 codec/native/FP32 或其他表示的相同输入。这是表示层比较，不是语义准确率。
5. **延迟**：单请求先 warmup 20 次，再测量 50 次；报告 median、nearest-rank p95、min、max 和后端。延迟样本不得作为语义分数。

## Sequence and stress plan / 序列长度与压力计划

- Primary application setting: `SEQ_LEN=90`, `MAX_OPTIONS=16`.
- Input validation case: reject or report overflow for input exceeding 512 tokens; never silently truncate to 90.
- Optional model-compatible stress points: 512, 1024, and 4096 tokens. Measure only when the selected model declares support; otherwise report unsupported rather than extrapolate.
- Keep semantic accuracy and stress/latency measurements in separate result files.

- 主应用配置：`SEQ_LEN=90`、`MAX_OPTIONS=16`。
- 输入校验样本：超过 512 token 时应拒绝或报告超限，不得静默截断到 90。
- 可选模型兼容压力点：512、1024、4096 token。只有模型声明支持时才测量；否则记录 unsupported，不做外推。
- 语义准确率与压力/延迟结果分开保存。

## Exclusions / 边界

The dataset does not execute physical commands, train or tune a model, establish field accuracy, or prove that an NPU has no CPU operators. Audio capture and device-side command execution are outside this trial unless separately authorized and recorded.

数据集不执行实体命令，不用于训练或调优模型，不建立现场准确率，也不证明 NPU 没有 CPU 算子。除非另行授权并记录，本试验不覆盖录音和设备侧命令执行。

### Latency and context / 延迟与上下文

- Laya: median `19.669 ms` and nearest-rank p95 `19.809 ms` from an exploratory NX TRT512 backend-only run, `n=50`; load/host overhead was not measured. The actual assembled input budget was 72–117 tokens across the frozen rows. This is not a 5,000-token or 4,096-token result.
- Kev: Spark CPU native reference PyTorch, model-only p50 `1520.9 ms`, p95 `1612.3 ms`; end-to-end p50 `1521.7 ms`, p95 `1613.2 ms`, 20 warmups and 50 samples. The tested rows rendered 71–110 tokens. The Kev source declares larger serving/training limits, but this trial did not test those limits and does not establish a 5,000-token threshold. The CPU run used reference DeltaNet/conv kernels; no NX model inference was completed.
- Bekko: formal NPU latency remains unverified. The browser dynamic embedding test used prefix width 128 and document width 384; the fixed/native FP32 ONNX comparison used the same fixed 128/384 shape. These are tested shapes, not a claim of unrestricted context capacity. The source code describes a larger positional capacity for the v0 backbone, but it was not used as an operational claim here. The external WSL run compiled/exported the FP32 ONNX source model to an RKNN artifact (291,453,711 bytes, SHA-256 `18570b7a1e61a256a15a0040e9819bb1472f0743c12eaab3c5a8c8641803025f`, elapsed 7:07.94, peak RSS 5.176 GB); three WSL→Radxa/Spark transfers ended with SIGINT and no target file while both endpoints were online. The native export parity check covered one sample only (`max_abs_logit_error=0.0540218353`); the 77/120 quality result is not full numeric parity.
- Speed values must not be compared across these rows: they come from different devices, runtimes, variants, and measurement contracts.

- Laya：NX TRT512 探索性 backend-only 运行的 median 为 `19.669 ms`，nearest-rank p95 为 `19.809 ms`，`n=50`；未测量加载和主机侧开销。冻结样本实际组装长度为 72–117 token。本结果不代表 5,000 token 或 4,096 token。
- Kev：Spark CPU native reference PyTorch，model-only p50 为 `1520.9 ms`、p95 为 `1612.3 ms`；端到端 p50 为 `1521.7 ms`、p95 为 `1613.2 ms`，20 次 warmup、50 次采样。样本实际渲染长度为 71–110 token。Kev 源码声明了更大的 serving/training 限制，但本试验未测这些长度，也不建立 5,000 token 阈值。CPU 运行使用 reference DeltaNet/conv kernel；NX 没有完成模型推理。
