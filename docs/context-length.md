# 长上下文（8k）

本篇讲长上下文探针的结果：512 / 2048 / 8192 三个长度上的可用性、随植入位置的失效模式，以及多语言表现。

## 8k 上下文：不可用，且主因在模型

用"植入事实"构造有标准答案的样本（4 选 1，chance 25%）：

| seq | **ORT fp32（不含 fp16 误差）** | TRT fp16 | 延迟（nx / nano） |
|---|---|---|---|
| 512 | **52.5%**（+4.0σ，显著） | 52.5% | 18.9 / 22.0 ms |
| 2048 | 30.0% | 30.0% | 119.7 / 141.5 ms |
| **8192** | **36.0%**（+1.8σ，**与 chance 不可区分**） | 28.0% | 1303.8 / 1417.2 ms |

**不存在"随长度衰减的曲线"，而是 512 可用、2048 之后直接掉到 chance 附近。**
2048/8192 的失败**主要是模型本身**（fp32 参考自己就只有 30–36%），部署保真度（fp16 vs fp32）
是叠加的、次要的因素。

**位置效应明确**（长上下文的经典失效模式）：8192 上植入点贴 marker 时 8/10，最远端 **0/10**。

**多语言**：512 上五个语种（en/zh/es/ja/ar）表现一致（各 4–5/8），脚本差异不产生可测差异；
8192 上没有可用语种。

> 注：该探针是"从 ~8000 token 取回一个数、并在 3 个诱饵中绑定对类别"，比 laya 自身判定
> benchmark 更硬。laya README 记载的"~4000 token 内 20 条对 16–18 条"测的不是同一件事，
> 两边结论不冲突。
